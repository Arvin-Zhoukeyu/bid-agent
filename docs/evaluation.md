# 评测设计与结果

## 数据与运行范围

当前固定测试集有 **8 份自行编写的招标文件、74 条人工标注要求、9 份初始企业材料**。其中基线集 3 份/26 条、场景集 3 份/31 条、挑战集 2 份/17 条。挑战集加入中文序号、无编号条款、表格文本，以及“主要求有材料、附加约束无材料”的复合条件。标注见 `samples/gold.json` 与 `samples/gold_extended.json`。

「运行评测」每次重新执行离线规则提取、证据排序、状态判断及离线草稿模板，然后和固定标注比较。它不调用大模型，也不使用用户上传的文件或后来加入的材料。场景集中的三份文件也提供给用户手工试用，因此**不能视为完全盲测集**；挑战集用于揭露已知薄弱点。这些数据只能证明本项目测试集上的表现，不能外推到真实企业标书。

## 指标定义

| 指标 | 分子 / 分母 | 当前结果 |
| --- | --- | --- |
| 要求召回率 | 找到的标注要求 / 全部标注要求 | 69/74 = **93.2%** |
| 要求精确率 | 找到的标注要求 / 全部提取要求 | 69/69 = **100.0%** |
| 状态判断准确率 | 状态正确的已找到要求 / 已找到要求 | 64/69 = **92.8%** |
| 首要证据准确率 | 首条推荐材料与标注一致的已找到要求 / 已找到要求 | 65/69 = **94.2%** |
| 端到端正确响应率 | 提取、首要证据、状态和草稿保护均通过的要求 / 全部标注要求 | 60/74 = **81.1%** |
| 错误判为有依据率 | 实际证据不足却被判“有依据”的要求 / 被判“有依据”的要求 | 4/34 = **11.8%** |

“端到端”中的草稿保护只检查：缺口是否明确写为不作符合性承诺、待确认与待跟进是否保留风险标记、有依据响应是否关联首要材料。这是**模板结构检查，不是人工事实核验或模型幻觉率**。要求召回的分母包含漏提条款，因此端到端指标不会被只在已提取条款上计算的状态准确率抬高。

挑战集的 17 条要求中只提取到 13 条，端到端通过 8 条；4 条复合条件被错误判为“有依据”。这比单看总体精确率更能反映当前风险：规则命中主关键词时，尚不能可靠核验附加的驻场人数、恢复时限和证明材料。

## Token 用量

从本版本开始，模型 API 成功响应后会记录服务商返回的 `usage.prompt_tokens`、`usage.completion_tokens`、`usage.total_tokens` 和响应耗时；只保存用量元数据，不保存提示词或模型回复。Web 评测页累计展示实际返回的 Token。服务商未返回 `usage` 时显示“未返回”，历史调用无法补记；**离线固定评测消耗 0 Token**。Token 用量不是质量指标，需和质量、延迟及人工工时一起分析，才能估算业务 ROI。

## 仍需补充的验证

目前没有真实客户授权数据、多人盲标、模型模式的独立效果评测或人工计时对照实验。因此不能声称真实标书准确率、实际节省工时、模型幻觉率或生产成本。下一步应扩大不同格式和行业的留出集，对复合条款做字段级核验，并用授权样本测模型质量与人工返工时间。
