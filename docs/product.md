# 标策 BidPilot 产品方案（作品集版）

## 1. 项目定位

目标用户：软件服务企业的售前人员、投标专员。核心任务：从招标文件中整理必须响应的要求，查找企业已有资料，形成有来源的技术响应初稿与缺口清单。

**业务假设**：复杂招标文件的条款梳理、材料查找和初稿编写占用大量重复劳动，遗漏重要条款和误用过期资料会增加返工。此假设尚未由真实用户访谈验证；当前版本使用合成数据做产品可行性演示。

## 2. 目标与非目标

本版本目标：让用户在同一工作台完成要求提取、证据匹配、状态判断、人工确认、初稿生成和导出；每条要求保留原文行号和推荐材料。支持本地使用与无模型密钥演示。

本版本未覆盖：扫描件 OCR、完整招标文件排版、商务报价计算、资质真实性验证、多人协作、权限与审计、正式投标提交。真实企业使用前必须解决安全与合规、文件解析和质量验证。

## 3. 用户旅程

1. 上传可复制文字的招标文件。
2. 系统识别编号条款，归为资格、技术、商务交付和时间节点。
3. 系统从企业材料库检索相关证据，将条款标为“有依据、待确认、材料缺口、待跟进”。
4. 用户逐条查看原文、材料摘录和判断理由，手动确认或标记需处理。
5. 遇到材料缺口或待确认项时，用户可以从条款详情直接补充企业材料；系统保存材料后重新匹配现有条款并使旧初稿失效。
6. 系统生成标书初稿，包含响应表、逐条响应、实施与服务方案框架、缺口待办和引用材料。缺材料时明确保留缺口，不作符合性承诺。
7. 用户导出完整 Word 初稿，补充报价、签章、具体人员与正式证明材料后继续人工编辑。

## 4. 关键产品决策

- **要求—证据—响应三栏关系**：让用户能从生成文本回看出处，降低核查成本。
- **缺口优先**：案例数量不足、人员证书缺失、服务时限未承诺等情况显示为缺口，避免“看起来符合”的错误结论。
- **确定性本地流程**：无 API 密钥时仍可走通演示，便于复现与评测。配置模型后仅对已有证据支持的条款做语言生成。
- **人工审核显式化**：每条要求有独立审核状态，产品结果定位为辅助初筛和草稿。
- **缺口闭环**：从缺口条款直接补材料并自动重算状态；重算沿用已提取条款，不额外调用模型，生成新初稿时才使用更新后的证据。

## 5. 信息结构与实现

- 项目：文件、提取文本、要求列表、标书初稿及导出记录。
- 要求：编号、类别、原文行号、状态、判断理由、推荐证据、审核状态。
- 材料：名称、类别、正文、有效期。
- 评测：标注条款、期望状态、提取与判断结果、错误案例。

文档处理支持 TXT、PDF、DOCX 的可复制文本。离线模式下，要求提取使用编号与约束词规则；配置模型后，模型先抽取可对应原文行号的要求，本地工具再检索材料并判断状态。证据检索使用中文二/三元词项重叠；判断采用显式业务规则；模型还可生成有材料支持的响应语句。8 份文件、74 条标注要求的固定评测集测量的是**离线基线**，分开呈现条款、首要证据、状态、草稿模板及错误判“有依据”的风险；已发现中文序号漏提和复合约束误判。模型模式尚未完成独立标注评测。模型 API 的真实 Token 用量从启用记录后单独累计。

提示词采用文件化版本管理：`prompts/requirement_extraction_v1.txt` 约束条款抽取与原文定位，`prompts/bid_document_generation_v2.txt` 约束九章投标文件、逐条响应、商务报价和材料缺口。生成结果通过本地状态判断和数字集合校验，材料不足统一保留【待补充】。

## 6. 后续优先级

P1：扩展条款结构识别（中文序号、表格、跨行要求），增加 PDF 页面定位与 OCR；为数字时限、数量、证书等建立字段级验证。P2：企业资料版本和有效期提醒、引用片段精确定位、用户协同审核与操作日志。每项迭代均通过固定测试集和新收集的真实授权样本验证。

## 模型选型与验证状态

选用 `qwen3.5-plus-2026-04-20`。当前场景以中文要求抽取和短篇响应为主，需要结构化输出与足够的文本上下文；固定快照便于后续重复评测。项目通过 OpenAI 兼容 Chat Completions 调用该模型；在阿里云官方域名下抽取时关闭思考模式并请求 JSON Object，其他兼容接口使用提示词约束 JSON。代码仍逐条验证返回的原文行号与引文，支持的响应合并为一次模型请求，并拒绝凭空增加数字承诺的文本。资料参见[模型能力](https://help.aliyun.com/zh/model-studio/qwen3-5-plus)和[结构化输出说明](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

已通过用户配置的兼容接口完成真实调用：最小连通请求成功；内置虚构政务标书经模型抽取 10 条要求，批量生成 10 条响应并成功导出 Word。首次 20 秒超时后调整为默认 90 秒，并将草稿生成从逐条请求改成批量请求。**尚未做模型与其他候选的 A/B 对比或独立量化效果评测**；离线规则基线的数字不能归因于该模型。下一步应分别测试准确率、事实支持率、响应时间与单项目成本。

## 7. 面试展示建议

演示一个完整项目，重点指出“两个政务案例不足三个”和“4 小时恢复承诺缺失”如何被识别；再展示评测页中对中文序号的漏提，并解释下一轮迭代如何解决。明确说明数据是合成的，系统尚未经过真实企业生产验证。
