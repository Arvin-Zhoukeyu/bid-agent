# 简历与面试材料（请按实际参与情况调整）

## 项目名称

标策 BidPilot｜软件服务企业投标响应辅助 Agent（个人项目）

## 可直接采用的描述

围绕售前投标场景，设计并实现可运行的投标辅助产品原型：支持招标文件解析、要求结构化、企业资料检索、证据缺口提示、人工审核，以及覆盖项目概述、技术服务、实施、团队、质量保障、案例、响应表、商务和附件的正式结构化标书初稿与 Word 导出；以“要求—证据—响应”链路保证结果可核查。

构建 8 份合成招标文件、9 份合成企业材料与 74 条人工标注要求的分组评测集；在离线规则基线上测得要求召回率 93.2%（69/74）、端到端正确响应率 81.1%（60/74），识别出 4 条“材料不足却判为有依据”的复合条件风险，并据此明确字段级核验的下一轮迭代重点。

设计“有依据 / 待确认 / 材料缺口 / 待跟进”的产品状态和人工确认流程；对案例数量不足、未提供证书和缺失服务承诺进行显式提示，避免草稿作无依据承诺。

设计材料缺口闭环：用户可从具体条款直接补充企业资料，系统自动重新检索证据、更新符合状态并使旧初稿失效；再次生成时将新增材料写入逐条响应和引用清单。

- 这是个人原型项目，数据均为合成样例，尚无真实客户或生产使用数据。
- 当前检索为本地词项检索；配置兼容模型接口后可进行模型抽取和语言生成，不能把这个版本描述为已实现向量 RAG 或多 Agent 系统。
- 已用配置的兼容接口跑通 `qwen3.5-plus-2026-04-20` 的条款抽取与草稿生成；尚未完成独立模型评测，不能把上述质量数字归因于该模型。上述数字属于离线规则基线。
- Web 页面新增模型 API 返回的 Token 用量记录；只展示真实返回的 usage，不能把离线评测的 0 Token 说成模型运行成本。
- 评测样本小，数字应始终附带“在内置合成测试集上”的范围说明。
- 真实业务价值仍需用户访谈与同任务耗时实验验证，不能声称“提效 XX%”。

## 面试讲述顺序

业务假设 → 用户任务和流程 → 核心界面 → 为什么要求证据可追溯 → 如何处理材料不足 → 评测方法与 Bad Case → 下一步验证真实价值。

## 被问“为什么选这个模型”时

当前准确说法：

> 我选用 `qwen3.5-plus-2026-04-20` 固定快照，通过 OpenAI 兼容接口完成了真实调用。项目主要处理中文招标条款抽取和有证据约束的短篇生成，因此考虑中文能力、结构化输出、长文档处理和调用成本。代码把招标文本按约一万字符分块，请模型返回原文行号和引文；无效引文会被丢弃，再由本地检索与规则核验材料。内置标书已经跑通模型抽取、批量生成和 Word 导出；74 条合成数据上的 93.2% 要求召回率仍是离线规则基线，还不是模型效果。下一步会在同一标注集上测模型召回、事实支持率、耗时和成本，再决定是否保留选型。

完成独立模型评测后，才将具体质量指标写入模型成果。不要提前声称做过模型对比或生产部署。
