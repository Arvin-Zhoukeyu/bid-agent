# 标策 BidPilot：投标响应辅助 Agent

面向软件服务企业售前与投标专员的本地演示项目。上传招标文件，提取要求，检索企业材料，生成可核查的标书初稿，并输出缺口清单。项目内置**明确标注为虚构的**演示文件和一套可重复运行的评测集。

作品集材料：

- [产品需求文档（PRD）](BidPilot_PRD_AI产品经理作品集.docx)
- [项目汇报 PPT](BidPilot汇报.pptx)

## 启动

推荐在 Anaconda Prompt 使用 Python 3.10+ 独立环境；PDF、DOCX 解析与 DOCX 导出需要安装依赖：

```bat
cd /d F:\标书agent
conda create -n bidpilot python=3.11
conda activate bidpilot
python -m pip install -r requirements.txt
python check_api.py
python app.py
```

如果 `bidpilot` 环境已经创建，跳过 `conda create`；依赖装过也可跳过安装。打开 <http://127.0.0.1:8765>。首次启动会从 `samples/` 载入两个演示项目与企业材料。`data/state.json` 保存本地操作记录。

## 网页怎么用

网页不仅展示结果，也能调用后端 API 完成实际操作。第一次体验建议按下面顺序：

1. 打开「总览」了解项目数量和整体流程。点击「进入项目工作台」，在下拉框选择“市级政务服务平台运维服务”。
2. 在「项目工作台」点击左侧任一条要求，右侧会显示招标原文、判断原因和推荐企业材料。`有依据`表示找到了相关材料，但仍需核对原件；`待确认`表示现有材料不足以直接承诺；`材料缺口`表示缺少或不满足要求；`待跟进`常用于截止日期等需人工处理的事项。对于“材料缺口”和“待确认”，可以点击「补充此条款材料」，粘贴正文或上传文件；这里需要补充投标企业自身的证书、案例、人员清单或服务承诺，不能再次上传招标方的要求文件。保存后系统会立即重新匹配当前项目，并清除需要更新的旧初稿。
3. 用「未审核／已复核／需处理」记录人工审核意见。这三个按钮只记录审核状态，不会改变系统对条款的自动判断。
4. 点击「生成标书初稿」，系统形成响应概览、符合性响应表、逐条响应、实施与服务方案框架、缺口待办和引用材料清单。已有初稿时，按钮改为「查看已有草稿」；初稿页的「重新生成」才会再次调用模型。「导出完整 Word」下载可继续编辑的文档，提交前需补全报价、签章和人员信息，并人工核对依据与承诺。
5. 「企业材料库」用于添加资质、案例或产品方案。点击材料名称或「查看全文」可阅读完整正文。保存新材料后，回到项目工作台点击「重新分析」，项目才会用新材料重新匹配；重新分析会清除旧草稿。
6. 「新建项目」上传自己的 TXT、文字型 PDF 或 DOCX 并分析。模型配置有效时，分析和生成可能需要 1–2 分钟；页面会持续显示处理状态。若模型失败，会提示原因并回退至离线规则流程。
7. 「效果评测」基于 50 份招标文件、300 条人工标注要求运行固定测试集，查看要求进入证据评测率、首要证据一致率、端到端正确响应率、错误判“有依据”率及错例。离线评测不调用模型；同页的 Token 区域只累计启用记录后模型 API 实际返回的 usage。

## 能力与边界

- 支持 TXT、PDF、DOCX（可复制文字）输入；扫描件 OCR 尚未实现。
- 无密钥时用本地规则提取要求、中文词项检索材料、规则判断缺口，完整演示业务流程。
- 在项目根目录的 `.env` 填入 `LLM_API_KEY` 后，**新建项目或点击「重新分析」**会调用 OpenAI 兼容的 Chat Completions 接口提取要求，随后由本地工具检索材料、判断状态；「生成标书初稿」还会调用模型生成有材料支持的响应。模型返回的条款必须能对应文件原文，否则会被丢弃；调用失败时界面会提示并回退到离线规则分析。AI 输出仍需人工审核。
- 企业资料、招标文件和企业名称均为**合成演示数据**，没有真实客户或生产使用数据。项目可写入简历，但不要把模拟数据说成真实业务成效。
- 数据默认保存在本机，没有用户鉴权与多租户隔离；不用于处理真实敏感标书。

## 目录

`app.py` HTTP 服务与 API；`engine.py` 文档处理、抽取、检索、生成与评测；`prompts/` 存放可独立查看和迭代的提示词版本；`web/` 前端；`samples/` 合成数据与标注；`docs/` PRD、评测说明和简历表述。

## 启用模型

项目已提供 `.env`（空密钥）和可共享的 `.env.example`。用文本编辑器打开根目录 `.env`，将 `LLM_API_KEY=` 后面填入**你自己的百炼 API Key**，保存并重启服务。其他两项已按本项目的候选模型预填：

```dotenv
LLM_API_KEY=你的密钥
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen3.5-plus-2026-04-20
LLM_TIMEOUT_SECONDS=90
```

`.env` 已加入 `.gitignore`，不要上传、截图或提交含密钥的文件。程序启动时自动读取它；如果系统环境变量中也设置了同名值，则优先使用系统值。无需密钥也可体验离线流程。

先单独测试 API，再运行完整程序：

```powershell
python check_api.py
python app.py
```

`check_api.py` 仅发送一句测试文本，不上传招标文件；只显示调用结果、模型名称、接口域名和耗时，不打印密钥或回复正文。退出码为 0 表示连通，1 表示请求失败，2 表示配置缺失。完整程序启动后在项目工作台点击「重新分析」，再生成草稿验证整个流程。

接口地址填服务商提供的 **API 基础地址**，不要填网页聊天地址，也不要在末尾再加 `/chat/completions`。设置完成后，页面右上角会显示模型名称。选择演示项目点击「重新分析」，项目标签应显示「模型抽取 + 本地证据检索」。若接口地址、模型名或密钥错误，项目页会显示回退原因。模型调用会将招标文本或相关材料片段发送到所选服务商；真实企业文件需先确认使用权限。

该模型是基于中文文本、结构化输出、上下文能力及成本选择的方案。已用内置虚构标书验证真实 API 连通、模型条款抽取、批量响应生成与 Word 导出。当前固定评测集包含 50 份招标文件和 300 条人工标注要求：要求进入证据评测率为 93.0%（279/300），首要证据一致率为 93.9%（262/279），端到端正确响应率为 81.3%（244/300），错误判为“有依据”的比例为 11.8%（4/34）。这些结果用于说明离线规则基线及评测方法，不代表线上真实业务成效。模型与接口说明：[模型能力](https://help.aliyun.com/zh/model-studio/qwen3-5-plus)、[OpenAI 兼容调用](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)、[API Key 获取](https://help.aliyun.com/zh/model-studio/get-api-key)。
